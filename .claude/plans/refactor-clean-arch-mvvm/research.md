## Acceptance Criteria (Finalized)

### Functional Requirements

#### Onboarding
- [ ] Onboarding screen appears only on first launch; a `shared_preferences` flag (`onboarding_seen`) suppresses it thereafter. (source: I)
- [ ] Onboarding can route to Login (default), Guest (Anonymous auth) or Signup via a CTA row on the last page. (source: I)

#### Auth
- [ ] Email/password sign-up, sign-in, password reset retained. (source: C)
- [ ] Google sign-in added (`google_sign_in` package). (source: I)
- [ ] Anonymous (guest) sign-in added via `FirebaseAuth.signInAnonymously()`. (source: I)
- [ ] Email verification required before a user can access community (post/like/comment); unverified users see a "verify your email" banner with a resend CTA. (source: I)
- [ ] On password reset success, show a snackbar and auto-navigate back to Login after ~2s. (source: I)
- [ ] Logout clears auth state and returns to HomeScreen; the drawer's Logout item triggers this. (source: C)

#### Home & Navigation
- [ ] HomeScreen is the post-auth hub: greeting uses `FirebaseAuth.currentUser.displayName` (not hardcoded "Anirban"), or "Guest" for anonymous users. (source: C)
- [ ] Bottom nav: Home, Mountains, Community, Profile. (source: I)
- [ ] Drawer retained but trimmed to functional items only: Profile, Liked Mountains, Logout. (source: I)

#### Mountains (browse + search + likes + weather)
- [ ] Mountain list loaded from Firestore `mountains` collection (seeded once from `assets/hill_station.json`); `hill_station.json` kept in repo as a dev fallback. (source: I)
- [ ] Each mountain card shows weather fetched from OpenWeatherMap; weather response cached per session to avoid re-fetch on every render. (source: I)
- [ ] Search simplified to a local/Firestore filter over `mountains.name` and `mountains.description`; Nominatim + Overpass APIs removed. (source: I)
- [ ] Per-user liked mountains stored under `users/{uid}/private/likedMountains` (array of mountain IDs). Liking requires auth (not guest). (source: I)

#### Checklist
- [ ] Per-user checklist stored in Firestore under `users/{uid}/checklist/{itemId}` with fields `text`, `isDone`, `createdAt`. (source: I)
- [ ] Checklist requires auth (guests see an empty-state CTA to sign up). (source: I)
- [ ] Add / toggle / delete items supported. (source: C)

#### Community
- [ ] Posts migrated from Realtime DB to Firestore `posts/{pId}` with fields: `pId`, `pTitle`, `pDescription`, `pImage`, `pTime` (server timestamp), `uid`, `uEmail`, `uName`, `likes` (array of uids). (source: I)
- [ ] Comments stored under `posts/{pId}/comments/{commentId}` with `text`, `commentedBy` (uid), `commentedByName`, `commentedAt` (server timestamp). (source: C)
- [ ] Feed uses a real-time Firestore snapshot stream, ordered by `pTime` descending. (source: I)
- [ ] Create post: image required; image compressed with `flutter_image_compress` before upload to Firebase Storage. (source: I)
- [ ] Owner-only delete post (removes post doc + cascades Storage image + comments subcollection). (source: I)
- [ ] Owner-only edit post (title + description only; image unchanged). (source: I)
- [ ] Owner-only delete comment. (source: I)
- [ ] Comment UX changed: inline comment input at bottom of the blog detail sheet, persistent above keyboard. (source: I)
- [ ] Per-post likes: tap heart → uid appended/removed from `likes` array atomically. (source: C)

### API Contract

#### Firestore Collections

| Collection | Doc shape | Read | Write |
|---|---|---|---|
| `users/{uid}` | `displayName`, `email`, `photoURL`, `createdAt` | by uid | self-only |
| `users/{uid}/private/likedMountains` | `{ mountainIds: string[] }` | by uid | self-only |
| `users/{uid}/checklist/{itemId}` | `{ text, isDone, createdAt }` | by uid | self-only |
| `mountains/{id}` | `{ name, imageUrl, description, region? }` | any authed user (+ guest) | admin only (no in-app admin) |
| `posts/{pId}` | `{ pId, pTitle, pDescription, pImage, pTime, uid, uEmail, uName, likes: string[] }` | any authed verified user | create: authed verified; update/delete: owner only |
| `posts/{pId}/comments/{cId}` | `{ text, commentedBy, commentedByName, commentedAt }` | any authed verified user | create: authed verified; delete: owner only |

#### External HTTP APIs
- **OpenWeatherMap** (`api.openweathermap.org/data/2.5/weather`) — retained; API key moved to `.env`.
- **Nominatim + Overpass** — removed.

#### Firebase Auth
- Providers: `EmailPassword`, `Google`, `Anonymous`.
- Email verification: `sendEmailVerification()` called post-signup; verified status checked at community gate.

### Validation & Error Handling
- [ ] All Repository / UseCase methods return `Result<T>` (hand-rolled sealed class: `Success(T)` | `Failure(AppError)`). (source: I)
- [ ] `AppError` hierarchy: `NetworkError`, `AuthError`, `NotFoundError`, `PermissionError`, `ValidationError`, `UnknownError`. (source: I)
- [ ] Every Cubit emits one of: `Initial`, `Loading`, `Success(data)`, `Empty`, `Failure(message)`. (source: I)
- [ ] No `print(error)` calls; all errors logged via a single `Logger` core utility and surfaced in UI. (source: C)
- [ ] All `StreamBuilder`/`FutureBuilder` instances removed in favor of `BlocBuilder` except where Firebase-native streams are wrapped by the data source. (source: I)
- [ ] Form validation: email format, password ≥8 chars with one letter + one digit, required fields non-empty, comment ≤500 chars, post title ≤80 chars, description ≤2000 chars. (source: I)
- [ ] Post image: required; rejected if compressed size >2MB after compression; friendly error surfaced. (source: I)

### Authorization & Permissions
- [ ] Guest (anonymous) scope: onboarding, mountain browse, mountain search, weather view. (source: I)
- [ ] Signed-in verified scope adds: checklist, likes, community read/create, comments. (source: I)
- [ ] Signed-in unverified scope: same as guest + pending verification banner with resend CTA. (source: I)
- [ ] Firestore security rules enforce: `users/{uid}/**` self-only, `posts` owner-only writes, `mountains` read-only client-side. Rules authored in this refactor; deployment not required to complete the iteration. (source: I)
- [ ] Route guards in `go_router` redirect unauthed users attempting to access gated routes. (source: I)

### Data & Storage
- [ ] Migrate existing RTDB `Posts/Post List/*` to Firestore `posts/*` via a one-shot script (dev data only; no production users, per user statement). (source: I)
- [ ] Seed `mountains` collection from `assets/hill_station.json` via `tool/seed_mountains.dart` script. (source: I)
- [ ] Remove `firebase_database` dependency after community migration completes. (source: I)
- [ ] Firebase Storage layout: `posts/{uid}/{timestamp}.jpg` (replaces current flat `/monuments_app{ts}`). (source: I)

### Side Effects & Integrations
- [ ] Weather fetch cached in-memory per `MountainsCubit` instance. (source: I)
- [ ] Image picker / compression runs off-UI on a background isolate where possible. (source: D)
- [ ] No background jobs / push / analytics in this refactor. (source: I)

### Edge Cases
- [ ] Network-offline on app launch: auth state hydrates from Firebase local persistence; data screens render cached/empty with retry CTA. (source: D)
- [ ] Anonymous user upgrading to email: `linkWithCredential` flow preserves their anonymous uid so likes/checklist carry over. (source: I)
- [ ] User deletes own account during a session: subsequent writes fail with `PermissionError`; UI bounces to Login. (source: D)
- [ ] Comment by a user who later deletes their account: comment retained but shows "Deleted user" as `commentedByName`. (source: D)
- [ ] Concurrent likes on the same post: `FieldValue.arrayUnion` / `arrayRemove` handle atomicity. (source: C)
- [ ] Post image upload fails: post creation aborts; no orphan post document. (source: D)
- [ ] Deep-linking / back-button: `go_router` handles system back; no custom `WillPopScope` needed. (source: D)

### Test Requirements
- [ ] Unit tests for every UseCase — happy path + each `AppError` failure mode. (source: I)
- [ ] `bloc_test` tests for every Cubit covering state transitions from `Initial → Loading → (Success | Empty | Failure)`. (source: I)
- [ ] Widget tests for each shared widget: `AppButton`, `AppTextField`, `AppPasswordField`, `AppCard`, `LoadingOverlay`, `EmptyState`, `ErrorView`, `FeatureCard`. (source: I)
- [ ] Mocks via `mocktail`. (source: D)
- [ ] Integration / golden / end-to-end tests are deferred. (source: I)

### Non-Goals
- Dark theme.
- Tablet / foldable layouts.
- Push notifications, deep-link URLs, analytics.
- Admin UI to manage mountains.
- iOS-specific polish beyond default Material rendering.
- Performance tuning beyond image compression.
- Production-grade Firestore rules deployment (rules authored but deploy is an ops task).

### Sibling Patterns
- No existing sibling patterns at the feature level — the codebase has no Cubits, no Repositories, no UseCases, and only a single GetX controller (`onboarding_controller.dart`).
- Existing patterns to preserve selectively: `cached_network_image` usage, Lottie loading animations (for polish), `introduction_screen` package for onboarding.

### Data Layer (Target)
- **Firestore**: 4 top-level collections (`users`, `mountains`, `posts`) + 3 subcollections (`users/{}/private`, `users/{}/checklist`, `posts/{}/comments`).
- **Firebase Auth**: Email/Password, Google, Anonymous, with email-verification on email/password.
- **Firebase Storage**: `posts/{uid}/{timestamp}.jpg`.
- **HTTP**: OpenWeatherMap only.
- **Realtime DB**: removed after Iteration 4.
- **Local assets**: `assets/hill_station.json` retained as seed + dev fallback.

### Integration Points
- Weather service called from `MountainsCubit.loadMountains`; results cached for session.
- Image compression called from `CreatePostCubit.submit` before Storage upload.
- Firestore security rules in `firestore.rules` at repo root; deploy is out of scope but rules are authored and committed.

### Permission Patterns (Target)
- `go_router` `redirect:` reads current `AuthState` from `AuthCubit`; gated routes bounce unauthed users to `/login`, unverified users to `/verify-email`, and allow guests through on non-gated routes.
- Firestore rules are the second layer of defense (never trust client gating).

### Test Patterns (Target)
- Unit tests: `test/unit/features/<feature>/domain/usecases/*_test.dart` — constructor takes a mocked repository, asserts `Result<T>` output.
- Cubit tests: `test/unit/features/<feature>/presentation/cubit/*_test.dart` — uses `bloc_test` + `mocktail`.
- Widget tests: `test/widget/shared/*_test.dart` — pump widget with theme, verify render + interaction.

## Q&A Summary

Decisions captured during Q&A (with rationale):

1. **State management → BLoC/Cubit.** User chose strict separation & testability over GetX/Provider.
2. **Rollout → Phased by feature (5 iterations).** Each iteration ships a working app.
3. **UI goals → all four.** Design system + loading/error/empty states + navigation + responsive.
4. **Feature scope → open to rationalizing.** Permits deleting dead files and trimming the drawer.
5. **Posts store → migrate to Firestore.** Unifies data and fixes the latent likes/comments-target-missing-doc bug.
6. **Checklist persistence → per-user Firestore.** Cross-device sync; gated behind auth; guests see empty-state CTA.
7. **Stack → go_router + get_it + hand-rolled Result<T>.** Minimal deps, declarative routing with guards, explicit errors.
8. **Onboarding → first-launch only** via `shared_preferences` flag.
9. **Liked mountains → per-user** at `users/{uid}/private/likedMountains`. Fixes shared-state bug.
10. **Auth methods → email/password + Google + Anonymous + email verification.** Broader reach with guest-friendly onboarding.
11. **Post CRUD → owner delete/edit; owner delete comment.** Requires security rules.
12. **Drawer → keep but trim.** Profile, Liked Mountains, Logout. Remove Friends/Share/Request/Settings/Policies.
13. **Guest scope → browse-only.** Guests: onboarding, mountains, search, weather. Verified users only: checklist, likes, community.
14. **Mountain data source → Firestore `mountains`**, seeded from `hill_station.json`.
15. **Mountain search → local-filter only.** Nominatim + Overpass removed.
16. **Post images → compress + required.** `flutter_image_compress` ensures reasonable payload; posts must have an image.
17. **Seed strategy → one-shot script** (`tool/seed_mountains.dart`), JSON kept for dev fallback.
18. **Comment UX → inline input** at bottom of blog detail sheet.
19. **Feed → real-time stream.** Matches current behavior.
20. **Password reset → snackbar + auto-return to Login.**
21. **Iteration count → 5, approved as-is.**
