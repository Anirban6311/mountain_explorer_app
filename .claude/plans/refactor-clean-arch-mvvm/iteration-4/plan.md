## 2. Architecture
- Clean + MVVM slice at `lib/features/community/`.
- **FeedCubit** streams `posts/` ordered by `pTime desc` via Firestore snapshots, maps to `PostsLoaded` / `PostsError`.
- **PostDetailCubit** combines: a) post stream (for owner-gated controls + likes) b) comments stream.
- **CreatePostCubit** handles: pick image → compress → reject >2MB → upload → create Firestore doc → surface Success. Abort creates doc if upload fails (no orphan).
- **EditPostCubit** updates title/description only. `imageUrl` untouched.
- Domain returns `Result<T>` for commands; streams stay raw (Iteration 1 convention).
- Community tab in `HomeShell` now renders `FeedPage` instead of the "coming soon" placeholder.

### Error/status mapping
- Firestore `permission-denied` → `PermissionError`
- Firestore `unavailable` / SocketException → `NetworkError`
- Image compression missing / >2MB after compress → `ValidationError('Image too large.')`
- Storage upload failure → `UnknownError('Image upload failed.')`

## 3. Storage Design

### Firestore
```
posts/{pId}:
  pId:          string          (== doc id)
  pTitle:       string          1..80 chars
  pDescription: string          1..2000 chars
  pImage:       string          Storage download URL
  pTime:        Timestamp       server timestamp on create
  uid:          string
  uEmail:       string
  uName:        string
  likes:        string[]        uids (arrayUnion/Remove)

posts/{pId}/comments/{cId}:
  text:              string      1..500
  commentedBy:       string      (uid)
  commentedByName:   string
  commentedAt:       Timestamp   server timestamp
```

### Storage
- Path: `posts/{uid}/{timestamp}.jpg` (replaces legacy flat `/monuments_app{ts}`).
- Compression with `flutter_image_compress`: quality 70, target ≤1MB; post-compress size >2MB → reject.

### Security Rules (authored this iteration in `firestore.rules` at repo root; deployment out of scope)
```
match /posts/{postId} {
  allow read: if request.auth != null;
  allow create: if request.auth != null
             && request.auth.token.email_verified == true
             && request.resource.data.uid == request.auth.uid;
  allow update: if request.auth != null
             && resource.data.uid == request.auth.uid
             && (request.resource.data.diff(resource.data)
                   .affectedKeys().hasOnly(['pTitle','pDescription','likes']));
  allow delete: if request.auth != null
             && resource.data.uid == request.auth.uid;

  match /comments/{commentId} {
    allow read: if request.auth != null;
    allow create: if request.auth != null
               && request.auth.token.email_verified == true
               && request.resource.data.commentedBy == request.auth.uid;
    allow delete: if request.auth != null
               && resource.data.commentedBy == request.auth.uid;
  }
}
```

## 5. Edge Cases
1. **Image >2MB after compression** → `ValidationError`; create flow aborts cleanly.
2. **Storage upload fails** → Firestore doc not created. No orphan.
3. **User deletes own account mid-session** → write fails with `permission-denied` → PermissionError → UI bounces to `/login`.
4. **Comment by user who later deletes their account** → display `commentedByName || 'Deleted user'`.
5. **Anonymous user taps "Create Post"** → FAB disabled; if reached via deep link, cubit rejects with `AuthError`.
6. **Unverified user taps "Create Post"** → router redirects to `/verify-email`.
7. **Concurrent likes on same post** → `arrayUnion/arrayRemove` atomic.
8. **Deep link to non-existent /community/post/:id** → `NotFoundError`; show friendly empty state with "Back to feed" button.
