## 2. Architecture Decision

### Chosen Approach

**Core-only infrastructure, no feature modules.** Every new capability lands under `lib/core/` as a thin service wrapper around a Flutter plugin, following the exact pattern used by the existing `AppPrefs` / `DotenvEnv` singletons. Registration in `lib/core/di/injector.dart` right after `AppPrefs`.

Rationale:
- Matches the existing convention perfectly — no new patterns introduced, no cognitive overhead when reading the codebase.
- Service wrappers give Iterations 2–5 a stable, mockable API regardless of which plugin we use underneath. If `geolocator` needs replacing later, `LocationService` shields every caller.
- All four sqflite tables (`offline_regions`, `trek_breadcrumbs`, `sos_outbox`, `offline_routes`) are created at schema-version 1 so no later iteration has to ship a sqflite migration — lower risk, one-shot schema.
- Consent screen lives at `/consent/background-location` and is reachable but not yet gated. Iteration 2 (Map MVP) will wire it into the map's "enable tracking" flow; Iteration 5 will enforce it before `ACCESS_BACKGROUND_LOCATION` is requested.

### Alternatives Considered

1. **Defer sqflite to Iteration 4 when SOS needs the outbox.** Rejected: it would add an extra sqflite migration in Iter 4 (moving from no-db to 4 tables), and the ring-buffer table is needed for trek session breadcrumbs in Iter 2 anyway (even if not written to yet). One-shot schema is cheaper.

2. **Use Hive or Isar instead of sqflite.** Rejected: `sqflite` is the most common Flutter choice, has first-class FFI test support (`sqflite_common_ffi`), matches well to our relational data (foreign keys, indexes, queries like "last 50 breadcrumbs ordered by ts"). Hive/Isar shine for document stores — ours is relational.

## 4. Storage Design

### sqflite: `mountain_explorer.db`, schema version 1

All four tables are created at v1. Iteration 1 does not write to them; Iterations 2/4/5 own their data. Types use SQLite affinity rules.

#### Table `offline_regions`
Catalog of downloaded tile regions. Iteration 2 writes.

```sql
CREATE TABLE offline_regions (
  id             TEXT    PRIMARY KEY,            -- uuid v4
  name           TEXT    NOT NULL,                -- user-visible label
  bbox_wkt       TEXT    NOT NULL,                -- 'POLYGON((lng lat, ...))'
  min_zoom       INTEGER NOT NULL,
  max_zoom       INTEGER NOT NULL,
  tile_count     INTEGER NOT NULL DEFAULT 0,
  size_bytes     INTEGER NOT NULL DEFAULT 0,
  downloaded_at  INTEGER NOT NULL,                -- epoch ms
  status         TEXT    NOT NULL DEFAULT 'pending' -- pending|downloading|paused|complete|partial|failed
);
```

#### Table `trek_breadcrumbs`
Ring-buffer (capped at 500 rows in Iter 5). Iteration 5 writes.

```sql
CREATE TABLE trek_breadcrumbs (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  ts        INTEGER NOT NULL,                     -- epoch ms, client-side
  lat       REAL    NOT NULL,
  lng       REAL    NOT NULL,
  accuracy  REAL,                                  -- meters, nullable if fix is coarse
  altitude  REAL,                                  -- meters, nullable
  battery   INTEGER                                -- 0–100, nullable
);
CREATE INDEX idx_trek_breadcrumbs_ts_desc ON trek_breadcrumbs(ts DESC);
```

#### Table `sos_outbox`
Offline-queue for failed Firestore writes during SOS dispatch. Iteration 4 writes.

```sql
CREATE TABLE sos_outbox (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  payload_json    TEXT    NOT NULL,
  kind            TEXT    NOT NULL,                -- 'alert' | 'breadcrumb'
  attempts        INTEGER NOT NULL DEFAULT 0,
  next_attempt_at INTEGER NOT NULL,                -- epoch ms
  created_at      INTEGER NOT NULL                 -- epoch ms
);
CREATE INDEX idx_sos_outbox_next ON sos_outbox(next_attempt_at ASC);
```

#### Table `offline_routes`
Trail overlays per region. Iteration 6 writes (deferred), but schema lands now to avoid a future migration.

```sql
CREATE TABLE offline_routes (
  id        TEXT PRIMARY KEY,
  region_id TEXT NOT NULL,
  name      TEXT NOT NULL,
  geojson   TEXT NOT NULL,
  FOREIGN KEY (region_id) REFERENCES offline_regions(id) ON DELETE CASCADE
);
CREATE INDEX idx_offline_routes_region ON offline_routes(region_id);
```

### Index Strategy

| Index | Rationale |
|---|---|
| `idx_trek_breadcrumbs_ts_desc` | Ring-buffer trim and "last N breadcrumbs" query (Iter 5 payload builder). Descending to serve newest-first reads cheaply. |
| `idx_sos_outbox_next` | Retry scheduler wakes, SELECT WHERE `next_attempt_at <= now` ORDER BY `next_attempt_at` LIMIT N. Ascending to hit due items first (Iter 4). |
| `idx_offline_routes_region` | Lookup all routes for a region when it's deleted (cascade) or rendered (Iter 6). |
| `offline_regions.id` (PK) | Direct lookup by region id is the dominant access; PK is enough. |

## 5. API Design

No HTTP/Firestore contracts in this iteration. The "API" here is the Dart-level service interfaces that Iterations 2–5 consume. Each is a `get_it` singleton.

### `abstract class LocalDb`

```dart
abstract class LocalDb {
  /// Opens the underlying sqflite database. Safe to call multiple times.
  /// Idempotent — second call returns the same `Database`.
  Future<Database> open();

  /// Raw handle for feature-owned DAOs. Call only after `open()` resolves.
  /// `close()` is for tests + app shutdown; product code should never close.
  Database get db;

  Future<void> close();
}
```

**Implementation** `SqfliteLocalDb`:
- Opens `${getDatabasesPath()}/mountain_explorer.db`.
- `version: 1`, `onCreate: (db, v) => _migrateTo(db, 0, 1)`.
- `onUpgrade: (db, old, new) => _migrateTo(db, old, new)`.
- `_migrateTo` walks a `List<Migration>` in order, running each `up(db)` inside a transaction.
- `PRAGMA foreign_keys = ON` enabled in `onConfigure`.

### `abstract class LocationService`

```dart
abstract class LocationService {
  /// Whether foreground (`whileInUse`) location is already granted.
  Future<bool> hasForegroundPermission();

  /// Requests foreground location. Returns granted status.
  Future<bool> requestForegroundPermission();

  /// Whether Android `ACCESS_BACKGROUND_LOCATION` (or iOS `always`) is granted.
  Future<bool> hasBackgroundPermission();

  /// Must be called ONLY after the consent disclosure screen has been shown
  /// and accepted. Play Store policy: no background-location request without
  /// prior disclosure.
  Future<bool> requestBackgroundPermission();

  /// Single foreground fix. Respects the current permission state; throws
  /// `PermissionError` if not granted.
  Future<Position> getCurrentPosition({
    LocationAccuracy accuracy = LocationAccuracy.high,
    Duration timeout = const Duration(seconds: 15),
  });

  /// Stream of position updates. Caller owns subscription lifecycle.
  Stream<Position> positionStream({
    LocationAccuracy accuracy = LocationAccuracy.high,
    Duration interval = const Duration(seconds: 30),
  });

  /// Whether the device has location services enabled at the OS level.
  Future<bool> isLocationServiceEnabled();
}
```

**Implementation** `GeolocatorLocationService`: thin wrapper over the `geolocator` plugin. Errors from `geolocator` are caught and re-thrown as `AppError` subtypes so callers stay in the `Result<T>` idiom.

### `abstract class BatteryService`

```dart
abstract class BatteryService {
  /// Current battery level, 0–100. Returns null on platforms that don't expose it.
  Future<int?> level();

  /// Live stream emitted when battery level changes by ≥ 1%.
  Stream<int> onLevelChanged();

  /// True if the device is currently charging or plugged in.
  Future<bool> isCharging();
}
```

**Implementation** `BatteryPlusBatteryService`: wraps the `battery_plus` plugin.

### `abstract class ConnectivityService`

```dart
abstract class ConnectivityService {
  Future<bool> isOnline();

  /// Emits true when any connection is available, false when fully offline.
  Stream<bool> onConnectivityChanged();
}
```

**Implementation** `ConnectivityPlusConnectivityService`: wraps the `connectivity_plus` plugin; reduces `List<ConnectivityResult>` → `bool` (online if any result ≠ `none`).

## 7. Edge Cases & Error Handling

1. **sqflite open fails (disk full, corrupt db)** — `SqfliteLocalDb.open()` catches `DatabaseException`, logs via `Logger`, rethrows so `configureDependencies()` fails fast. App shows the existing Firebase-init error path rather than silently running with no DB. Covered in test.

2. **Geolocator throws on plugin-not-ready** (common in hot-restart scenarios) — `GeolocatorLocationService` catches and returns `false` from permission-check methods rather than throwing; `getCurrentPosition` wraps in try/catch and throws `NetworkError` / `UnknownError` from `core/errors/app_error.dart`. Callers stay in `Result<T>` idiom per V-6.

3. **Battery-level plugin unavailable** (desktop, emulator) — `level()` returns `null`. Iter 5 code must treat `null` as "unknown → assume 50%" to avoid false low-battery mode.

4. **Consent screen dismissed via back gesture** — same as "Not now": pops with `false`. `onWillPop` set to always allow — no trap.

5. **Dotenv missing MapTiler key** — `DotenvEnv` throws `ArgumentError` at construction, surfaced by `main()` as an uncaught exception. This is the existing pattern for `OPENWEATHER_API_KEY`.

6. **First-run on Android 14+ where POST_NOTIFICATIONS requires runtime request** — not requested in Iter 1; no notifications are scheduled yet. Iter 4 (SOS MVP) will add the runtime permission prompt before posting the "SOS active" notification.

7. **User re-opens app after revoking permissions** — `LocationService.hasForegroundPermission()` is the single source of truth; it re-checks the OS on every call (no cache). Iterations 2+ must call it before every `getCurrentPosition`.

## 8. Security Considerations

- **Input Validation**: Env values validated at construction (non-empty strings). Consent screen has no user input. sqflite DDL is static, no interpolation.
- **Authorization**: No Firestore writes in this iteration; existing `firestore.rules` unchanged. No new auth surface.
- **Data Sanitization**:
  - `LocalDb` schema uses typed columns (INTEGER, REAL, TEXT) — SQL injection cannot reach it because Iter 1 only runs static DDL. Future iterations must use parameterized `rawInsert`/`rawQuery` + `whereArgs`.
  - `.env.example` placeholder values documented as such; real `.env` is already in `.gitignore`.
- **Play Store policy (AZ-5)**: disclosure screen copy must explicitly include: (1) what location data is collected, (2) when it is collected, (3) that it is used for SOS breadcrumb delivery to the user's named emergency contacts via Firestore. Copy below, committed to page source:

  > **Why Mountain Explorer needs background location**
  >
  > To keep you safe on remote treks, Mountain Explorer can record a trail of your location points (latitude, longitude, accuracy, and altitude) while a trek is active, even when the app is in the background or your screen is off.
  >
  > When you trigger SOS, those points are sent with your current position and battery level to the emergency contacts you have added. Contact delivery happens via SMS on your phone and via Firebase (Google's cloud database) to contacts who use Mountain Explorer.
  >
  > You can stop a trek or cancel an SOS at any time — tracking stops immediately when you do.
- **Background-location permission request is gated** — `LocationService.requestBackgroundPermission()` is implemented to throw `StateError` if called before `requestForegroundPermission()` has been granted, enforcing the Android escalation flow by code, not just by policy.
