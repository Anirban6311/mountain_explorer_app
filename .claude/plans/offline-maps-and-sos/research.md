- [ ] **FR-12 [I]** SOS payload contains: lat/lng, accuracy, altitude, UTC timestamp, battery %, last 50 trek breadcrumbs, user uid/name/email, contacts notified list.
- [ ] **FR-13 [I]** On dispatch, in parallel: (a) native SMS deep-link with pre-filled body for each contact, (b) Firestore write to `sos_alerts/{alertId}` with payload.

- [ ] **API-1 [I]** Collection `sos_alerts/{alertId}` — owner-only create; fields `uid, createdAt, status (active|cancelled|resolved|timed_out), lat, lng, accuracy, altitude, batteryLevel, userName, userEmail, contactsNotified[], lastSeenAt`.
- [ ] **API-2 [I]** Subcollection `sos_alerts/{alertId}/breadcrumbs/{id}` — owner-only create; fields `ts, lat, lng, accuracy, altitude, battery`.
- [ ] **API-3 [I]** Subcollection `users/{uid}/emergencyContacts/{contactId}` — owner-only CRUD; fields `name, phone, relationship, isPrimary, createdAt`.
- [ ] **API-4 [C]** `createdAt` uses `FieldValue.serverTimestamp()`; breadcrumb `ts` uses client epoch ms (server time unavailable while queued offline).

### Edge Cases
- [ ] **EC-1 [I]** SOS fired offline → SMS opens (works without internet); Firestore doc + breadcrumbs queued in `sos_outbox`, flushed on reconnect.
- [ ] **EC-2 [I]** Battery < 5% → breadcrumb cadence drops to every 5 min; persistent notification reflects low-battery mode.
- [ ] **EC-3 [I]** App killed during active SOS → 6h client-side timeout writes `status: "timed_out"` on next launch if alert still active.
- [ ] **EC-4 [I]** User cancels SOS within 3s countdown → no Firestore doc written, no SMS opened, no tracking started.
- [ ] **EC-5 [I]** Map panned outside all cached regions while offline → neutral "No offline tiles here" overlay, no crash, user marker preserved.
- [ ] **EC-6 [I]** Region download interrupted → `offline_regions.status = 'paused'`, resumable from catalog.
- [ ] **EC-7 [I]** Storage full mid-download → abort, keep partial tiles, flag region `partial`, show remediation.
- [ ] **EC-8 [I]** Malformed route GeoJSON → render without overlay (Iteration 6 scope).
- [ ] **EC-9 [I]** Contact deleted mid-flight SOS → payload snapshots contacts at dispatch time, isolating the alert from later edits.
- [ ] **EC-10 [I]** Background location denied → SOS dispatches single-shot foreground GPS only; tracking disabled with inline notice.

## Q&A Summary

Three Q&A rounds were run; 13 decisions locked. See "Key Decisions" table at top of this document for full reference. Material decisions that affect architecture:

- **Tile provider (MapTiler)**: adds one required env var; legal/policy-compliant bulk download.
- **Background location (geolocator + native foreground service)**: MIT license, custom platform channel, more code but no vendor lock-in.
- **Mountain lat/lng backfill**: schema change touches `Mountain` entity, `MountainModel.fromFirestore`, Firestore seeder, and `firestore.rules` field-check list. Iteration 3.
- **Map tab in HomeShell**: route surface change in `app_router.dart` and `home_shell.dart`.
- **Global SOS FAB in shell overlay**: requires a new shared overlay widget wrapping `HomeShell` body, emitting to a single `SosCubit`.
- **Trek session explicit toggle**: decouples breadcrumb recording from SOS dispatch; breadcrumbs outlive an alert lifecycle.
- **SMS + Firestore only (no FCM, no Cloud Function)**: keeps Phase 2 free of backend dependencies.
- **iOS Firebase config in Iteration 1**: unblocks Firestore writes from iOS in later iterations.
- **Trail route overlays (FR-8) deferred** to optional Iteration 6.
